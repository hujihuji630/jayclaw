# Web UI v1.1 — Warm Document Redesign

**Date:** 2026-05-24
**Target version:** v1.1
**Scope:** `packages/jay-web-ui/` plus a small backend slice in `jay-agent-core` and `jay-web-ui` for message IDs, a truncate route, and a markdown export route.

## Goal

Replace the current cyberpunk/neon visual language with a warm, restrained,
documentary feel — distinct from claude.ai's house style — and add the handful
of features that a developer reaches for several times an hour: code-block
upgrades, a command palette, message copy/resend/edit, drag-and-drop upload,
keyboard shortcuts, and slash commands.

## Non-goals

- Mobile/responsive layout (deferred).
- In-conversation search (deferred to a later release).
- Mermaid / KaTeX / charts inside markdown (deferred).
- Multi-window or split views.
- Message threading or branching beyond the existing fork modal.
- A JavaScript test framework. Tests stay manual on the frontend.
- A frontend build chain (no npm, webpack, vite). Static assets only.

### Typography

- **Display / brand**: `'Fraunces', 'Source Serif 4', Georgia, serif`. Variable
  axes used: `'SOFT' 100, 'opsz' 144` for the welcome headline.
- **UI / body**: `'Inter', system-ui, sans-serif`. `font-feature-settings: 'cv11', 'ss01'`.
- **Mono**: `'JetBrains Mono', 'Geist Mono', ui-monospace, monospace`.

Type scale (rem, base 16): 0.75 / 0.8125 / 0.875 / 0.9375 (body) / 1.0625 / 1.25 / 1.5 / 2 / 2.75. Line-heights: 1.65 (body), 1.4 (UI), 1.5 (code).

Fonts are self-hosted under `static/fonts/`. The current Google Fonts
`<link rel="preconnect">` is removed.

### Radii and motion

- Radii: 4px (controls), 6px (modals/panels), 2px (inline tags). Never above 8px.
- Motion kept: 120ms ease-out fade-in for messages; 80ms color transition on hover.
- Motion removed: grain overlay, avatar-ring rotation, send-glow blur, all
  neon halos, chromatic-aberration effects.

### Identity touches

- Hover underlines on accent text use a 2px hand-drawn jitter via inline SVG
  `<path>` with `stroke-dasharray` plus minor irregular nodes — replaces the
  current solid-bar hover.
- All icons replaced with [Lucide](https://lucide.dev/) outline icons at
  1.5px stroke. The current geometric glyphs (◆◇◫◬⬡) go.
- Every N (default 5) message turns, a 60%-width `--border` rule is inserted
  between turns, with a small `§` mark centered — visual "chapter break" cue.

## Layout

### Top bar (slimmed)

Three slots only:

```
[ § session-title ]                                       [⬢ model ▾]  [⌘K]  [☾]
```

`Compact`, `Handoff`, `New Chat`, `History`, and the context meter all leave
the top bar. They migrate to:

- **Compact / Handoff / Fork / Export / Clear / New / History**: command
  palette and slash commands.
- **Context meter**: bottom-right corner of the input area (where "how much
  room is left" is contextually relevant).

### Left sidebar (regrouped)

Width drops from ~240px to **216px**. Sections are introduced by a small
Fraunces all-caps `§ label`, not the current heavy `.section-label`:

```
JayClaw                              ← Fraunces, no icon
v1.1 · online

§ 当前对话
  History · New · Search (⌘K)

§ 工作区
  Files · Skills · Tools · MCP

§ 设置
  Configuration · Theme
```

Icon set: Lucide. The current `nav-glow` element is removed.

### Chat body

- **No bubbles.** Messages render as full-width text blocks, capped at
  72ch (~720px) and centered. User turns get `--bg-surface-hover` as a
  faint background; assistant turns use `--bg-page`.
- Each message header: small Lucide icon + role name (`你` / `JayClaw`)
  on the left, hh:mm timestamp on the right in `--text-tertiary`.
- A 1px `--border` divider separates each message.
- 24px vertical gap between messages. Every 5 turns, the `§` chapter rule
  is inserted.
- On hover, three buttons appear at bottom-right of each message:
  `⎘ Copy` / `⟳ Resend` / `✎ Edit` (the latter only on the most recent
  user message).

### Input area

```
┌────────────────────────────────────────────┐
│ [attachments]                               │
│ Type a message... (drag files to attach)    │
│ [📎] [/]              [ 23% context ] [↑]   │
└────────────────────────────────────────────┘
   Shift+Enter newline · / commands · ⌘K palette
```

- Three rows tall by default, auto-grows up to 12 rows.
- Attachments preview is at the top of the input container, not floating
  outside it.
- Footer line is the keyboard cheatsheet, replacing the current marketing copy.

## Features

### D1 — Code blocks

- Renderer: [marked](https://marked.js.org/) v12 + [DOMPurify](https://github.com/cure53/DOMPurify) v3 replace the current hand-rolled regex in `app.js:renderContent`.
- GFM enabled: tables, task lists, strikethrough.
- Syntax highlight: [highlight.js](https://highlightjs.org/) v11, language
  bundle limited to: py, js, ts, tsx, jsx, json, bash, sh, sql, yaml, toml,
  md, html, css, diff, rust, go, dockerfile.
- Custom theme `static/styles/highlight.css` keyed to the palette: keywords
  `--accent`, strings `--danger`, comments `--text-tertiary italic`, numbers
  `#B8732E` (light) / `#D4934A` (dark).
- Block chrome: small language badge top-left (`text-tertiary`, JBMono);
  copy button top-right that flips to a `Check` icon for 1.5s after copy.
- Long blocks (>20 lines) collapse with an "Expand N more lines" footer.
- Inline `code` retains `--bg-code` background, 0.4em horizontal padding,
  2px radius.
- **Streaming behavior**: incoming SSE chunks append to a buffer and
  trigger a 200ms-throttled lightweight render that runs `marked` only.
  On `message_end`, a final pass runs `highlight.js` plus copy-button
  installation. This eliminates per-token highlight cost on the hot path.

### D2 — Command palette (⌘K)

- Trigger: `Cmd/Ctrl+K` anywhere; `Esc` or outside-click closes.
- One frontend module `modules/palette.js`. Sources are an array of async
  loaders, each returning `Item[]`:
  1. Static commands (New, Compact, Handoff, Fork, Export, Clear, Toggle
     theme, open Files/Skills/Tools/MCP/Config).
  2. `/api/sessions`
  3. `/api/files`
  4. `/api/skills`
  5. `/api/tools`
  6. `/api/models`
- Matching: [fuzzysort](https://github.com/farzher/fuzzysort) (~10KB).
- Caching: results memoized for 30s in module state. Open re-uses cache;
  background refresh is non-blocking.
- Empty query state: top 5 recent sessions plus the 6 most-used commands.
- Keyboard: ↑↓ select, Enter execute, Tab cycle category, Esc close.

### D3 — Message copy / resend / edit

- Each message gains an `id` (uuid7) at creation. `history` API returns it.
  Legacy sessions hydrate as `legacy-{idx}` (stable hash) on first load.
- Hover row at bottom-right of the message:
  - `⎘ Copy` — all messages. Copies raw markdown (not rendered HTML);
    button flips to a check for 1.5s.
  - `⟳ Resend` — user messages only. Calls truncate API for messages
    after the previous turn, repopulates the input with the message's
    raw text, places the cursor at end. **Does not auto-send.**
  - `✎ Edit` — only on the most recent user message. Same as Resend
    plus enters inline-edit mode immediately.
- New backend route `POST /api/messages/truncate` with body
  `{ "after_id": str }`, removes the named message and everything after
  it from the in-memory history (and persists if a session is loaded).

### D4 — Drag-and-drop upload

- Document-level `dragenter`/`dragleave` listeners use a counter to avoid
  child-element flicker.
- While dragging, the chat container shows a dashed `--accent` border
  overlay with the label `+ 拖放文件以附加`.
- `drop` reuses the existing `handleFileSelect` path; the attachment row
  re-uses the existing renderer.
- Coexists with the current paste-to-attach and the file-picker button.

### D6 — Keyboard shortcuts and `?` help

| Shortcut | Action |
|---|---|
| `⌘K` / `Ctrl+K` | Command palette |
| `⌘N` | New chat |
| `⌘/` | Toggle help modal |
| `Esc` | Close top-most panel/modal/dropdown |
| `⌘L` | Clear current view (does not delete history) |
| `⌘Enter` | Force-send (same as Enter) |
| `Shift+Enter` | Newline (existing) |
| `⌘↑` / `⌘↓` | Jump to previous/next user message |
| `/` (in empty input) | Open slash command list |
| `?` (when not focused on a textbox) | Open help modal |

Help modal: three columns (`Navigation`, `Editing`, `Actions`),
shortcuts on the left rendered with `<kbd>` (3px radius, JBMono),
description on the right.

### D7 — Slash commands

- Trigger: input text starts with `/` and the cursor is within the command
  token. A small floating panel pinned above the input shows up to 6
  candidates.
- Source: same static `commands` list as D2's first source.
- Built-in commands: `/compact`, `/handoff`, `/fork`, `/clear`, `/new`,
  `/export`, `/help`.
- Keyboard: ↑↓ select, Enter or Tab execute, Esc dismiss (input keeps text).
- Selecting a command **executes immediately** (does not require Enter to
  send), preventing the "I sent `/compact` as a chat message" footgun.

### Markdown export

- New route `GET /api/sessions/{id}/export.md` returns `text/markdown`
  with `Content-Disposition: attachment; filename="chat-<name>-<date>.md"`.
- Body is the alternating user/assistant turns; assistant turns keep their
  raw markdown (code fences intact). Tool calls and system blocks are
  excluded by default.
- Discoverable through `⌘K → 导出 Markdown` and `/export`. No top-bar button.

## Backend changes

### Message IDs

- `Message` in `packages/jay-agent-core/src/jay_agent_core/agent.py` gains
  `id: str = field(default_factory=...)` using uuid7 (or a small nanoid
  helper added to `jay_agent_core`).
- The `history` REST endpoint returns `id` per message.
- Persistence: existing session JSON files round-trip the new `id` field
  on save; on load, missing `id`s are filled in deterministically as
  `legacy-{idx}` (so resend/edit on imported sessions is still safe).

### SSE event additions (additive — old clients ignore unknown events)

- `message_start { id, role, ts }` — emitted once at the start of the
  assistant turn so the frontend can attach the id to the DOM node.
- `message_end { id, total_tokens }` — emitted at the end so the frontend
  can lock the id and run final-pass rendering (highlight + copy buttons).

The existing `chunk`, `tool_status`, `done`, `error` events are unchanged.

### Truncate route

```
POST /api/messages/truncate
{ "after_id": "<message-uuid>" }
```

Response 200 `{ "removed": <int> }`. Implemented in a new
`packages/jay-web-ui/src/jay_web_ui/routes/messages.py`.

### Context meter — incremental tokenization

`compute_utilization` in `packages/jay-agent-core/src/jay_agent_core/context.py`
currently re-tokenizes the full history on every call (flagged in the recent
efficiency review). Change `ContextManager` to keep `_last_count` and
`_last_msg_count`; only tokenize new messages, reset on workspace change /
new conversation / compact. Public API unchanged.

### Things that stay the same

`/api/files`, `/api/skills`, `/api/tools`, `/api/sessions`, `/api/mcp`,
`/api/models`, `/api/config`, `/api/vision-model`, `/api/compact`,
`/api/handoff`. The command palette and slash commands consume the existing
shapes.

## Frontend implementation strategy

### No build chain

- Static-only. Vendor scripts (`marked`, `dompurify`, `highlight.js`,
  `fuzzysort`, `lucide`) live under `static/vendor/`. CDN URLs are kept as
  optional fallback in code comments only.
- Fonts (Fraunces, Inter, JetBrains Mono) self-hosted under `static/fonts/`
  with `font-display: swap`. No third-party preconnect.

### Module split

`static/app.js` (1663 lines, monolithic) becomes the entry point and the
following ES Modules:

```
static/
├── app.js                    -- bootstraps, wires modules
├── modules/
│   ├── api.js                -- fetch wrapper, AbortController, 5s default timeout
│   ├── state.js              -- minimal pub/sub store
│   ├── chat.js               -- SSE pipeline, message DOM, hover row (D3)
│   ├── markdown.js           -- marked + DOMPurify + highlight.js + copy button (D1)
│   ├── upload.js             -- file-picker, paste, drag-drop (D4)
│   ├── panels.js             -- Files/Skills/Tools/MCP/Config + _panelFetch helper
│   ├── palette.js            -- ⌘K (D2)
│   ├── slash.js              -- / commands (D7)
│   └── shortcuts.js          -- key bindings + ? help (D6)
```

Loaded as `<script type="module" src="/static/app.js" defer>`.

### CSS split

`static/style.css` (1573 lines) becomes the entry, `@import`-ing:

```
static/
├── style.css                 -- @imports
├── styles/
│   ├── tokens.css            -- :root + [data-theme=dark] CSS variables
│   ├── base.css              -- reset, headings, p, a, kbd, code
│   ├── layout.css            -- 3-pane shell, sidebar, topbar, input area
│   ├── chat.css              -- message blocks, dividers, hover row, copy button
│   ├── panels.css            -- side panels and modals
│   ├── palette.css           -- ⌘K palette, slash list, help modal
│   ├── highlight.css         -- "jayclaw paper" highlight theme
│   └── animations.css        -- the few remaining keyframes / transitions
```

All cyberpunk classes are deleted outright (no compat shim): `.glow`,
`.grain-overlay`, `.avatar-ring`, `.avatar-ring-2`, `.nav-glow`,
`.send-glow`, etc.

### Theme switching without FOUC

A tiny inline script in `<head>` reads `localStorage.theme` (or
`prefers-color-scheme`) and sets `document.documentElement.dataset.theme`
before the stylesheet evaluates.

### Streaming rendering pipeline (anti-jank)

For each assistant turn:

1. `message_start` → create a DOM node with the id; mount empty content.
2. `chunk` events append raw text to a per-message buffer; a 200ms
   `requestAnimationFrame`-throttled callback renders `marked(buffer)`
   into the node. **No `highlight.js` here.**
3. `message_end` → final render pass runs `highlight.js` over each
   `<pre><code>`, installs copy buttons, then unlocks the id.

This addresses the per-token cost issue from the prior efficiency review.

## Implementation order (independently shippable steps)

1. **Tokens + base + self-hosted fonts.** Visual shifts immediately on the
   existing layout. Catches font/color regressions early.
2. **Layout reshape.** Top-bar slim, sidebar regroup, message blocks
   replace bubbles.
3. **D1 — markdown + highlight.js + copy + streaming throttle.** Replaces
   the regex renderer.
4. **D4 — drag-and-drop upload.** Trivial, pure addition.
5. **D2 — ⌘K command palette + fuzzysort.** Adds new module + vendor.
6. **Backend prerequisite — message ids + `message_start`/`message_end`
   SSE events + `/api/messages/truncate`.**
7. **D3 — copy / resend / edit hover row** (depends on step 6).
8. **D6 — keyboard shortcuts + `?` help modal.**
9. **D7 — slash commands** (reuses D2's commands list).
10. **Markdown export** (new sessions route + palette/slash entry).
11. **JS / CSS module split.** Done last, when behavior is stable, to
    minimize churn during feature work.

Each step is its own PR-sized commit. CI must stay green at every step.

## Risks and mitigations

- **Markdown injection.** Switching from regex to `marked` could regress
  XSS posture. Mitigation: pipe through DOMPurify with a strict allowlist
  (no `<script>`, no `on*` attrs, anchor `target="_blank" rel="noopener"`).
- **Vendor weight.** Total static-asset growth target ≤ 250KB gz combined
  for marked + DOMPurify + highlight.js + fuzzysort + lucide subset. If
  highlight.js is too heavy, drop language coverage further (top-8 only).
- **Message id migration.** Existing session files lack ids. Mitigation:
  `legacy-{idx}` hydration is deterministic; truncate works on both.
- **CDN vs local.** Vendor scripts default to local (`static/vendor/`)
  to keep offline / air-gapped use working. CDN is documentation-only.
- **Module ordering.** ES Modules with `defer` guarantees order-after-DOM,
  so the entry script can wire modules without race conditions.
